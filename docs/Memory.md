# MelBond — Persistent Project Memory

> Record verified facts and decisions. Update this file at every phase boundary.

## Identity
- Product: MelBond.
- Platform: Android-first.
- Audience: university student teams; initial team size 3–6.
- Principle: one project, one organized workspace.

## MVP scope
Auth/profile; projects and secure membership/invitations; customizable playbooks; tasks/filters; milestones/timeline; meetings/minutes; decisions; resources; notifications/activity; dashboard; optional Team Pulse; authorized search.
Out of scope: recruiting, replacing chat/Drive/GitHub, AI automation, university administration, member rankings, supervisor portal, web dashboard.

## Default stack
React Native + Expo + TypeScript; Expo Router; Supabase Auth/PostgreSQL/RLS/private Storage; Edge Functions/scheduled jobs; TanStack Query; React Hook Form + Zod; Expo Notifications/EAS Build where appropriate. Verify exact versions/compatibility during bootstrap.

## Non-negotiable decisions
- Client is untrusted.
- RLS and trusted server-side checks enforce access.
- Never ship service-role credentials in the app.
- Private project data/files by default.
- No member performance ranking.
- Future AI output must be reviewable and must not silently change records.
- No phase advances without explicit user authorization.

## Decisions to resolve
- [x] Expo SDK and minimum Android version: Resolved to Expo SDK 58 (React 19.3.0, React Native 0.88.1, Expo Router 58.0.28). Minimum Android target aligns with Expo SDK 58 defaults (Android 5.0+ / API 21+).
- [x] Email confirmation, reset, account recovery: Password reset requests sent via Supabase Auth client; sign-up requires valid email and password; session state persisted securely via AsyncStorage; sign-out clears session and local profile state.
- [x] Invitation target and delivery: 6-character high-entropy alphanumeric codes generated by client, stored with 7-day expiry, 5-use limit, and revocation flag. Redeemed atomically via PostgreSQL RPC `redeem_invitation`.
